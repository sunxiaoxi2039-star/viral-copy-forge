## 1. 通道说明

- 主通道：复用用户已登录的浏览器会话的采集桥（各人本机工具不同）。开跑前先验证登录态；未登录就停下来请用户登录，不绕行，不做免登录硬爬。
- 备选通道：All-IN-ONE CLI（aione douyin，45 条命令，覆盖搜索/详情/评论/用户/直播）。属登录态逆向通道，标注「谨慎使用、尊重平台规则」。
- 两者都不可用：如实写「抖音侧无法采集」，只跑小红书单平台口径，并按 SKILL.md 第⑤段数据完整性检查执行（交付物标「单平台证据」，文案禁跨平台措辞），不编数据。

## 2. 命令映射（与小红书对称）

| 动作 | 要拿到的东西 | 落到本仓的格式 |
|---|---|---|
| 搜索 | 关键词前 30 条：文案、作者、赞、链接 | `rows[]` 的 title/author/likes/url |
| 详情 | 视频文案里的话题 | `rows[].tags`（没有就留空，脚本从 text 抽 #） |
| 评论 | 评论区真实用户原话 | 不进火力表，只做③段语料 |

各家采集器命令不同，本仓不绑定任何一个。你的工具输出什么字段，按
`docs/DATA_SCHEMA.md` 映射成标准 JSON 即可（`scripts/normalize.py` 能帮你转 CSV/JSON）。
`examples/data/douyin-2026-09-19.json` 就是一份真实采集结果，可直接照抄字段。

抖音这边的现实：常见采集接口只稳定返回 likes，plays / comments / shares 恒为 0，
也不给发布日期——所以表头要写「仅 likes 口径」，且 90 天衰减闸对这批数据失效，
脚本会在表脚自动标注这一条。

## 3. 火力口径（与小红书不同，别照搬）

- 抖音看话题不只看单条：单 hashtag 火力 = 挂这个话题的视频累计 likes。
- 同一品牌话题多次出现合并计力（如 #达霏欣防脱洗发水 出现 3 次，就把 3 条视频的赞加总）。
- 开头句式按「以感叹/反转/提问切入」归纳，≥2 条样本重复出现才算「重复句式」，孤例不列。
- plays / comments / shares 接口常缺：缺就用 likes 单口径，并在表头写明「仅 likes 口径」。
- 闸门阈值（平台样本闸、话题最小样本闸、离群封顶、单条贡献上限）以 SKILL.md ④「火力闸门」为准，
  本册不重抄数字；跑 `python3 scripts/fire_table.py 你的抖音数据.json` 会把判定直接写进表里。
- 离群封顶在抖音尤其容易触发：2026-09-19 实抓的 20 条里，饿馒头一条 179.7 万赞，
  是样本中位数（2.05 万）的 87 倍——不封顶的话，整张表等于给一条视频做汇报。

## 4. 副话题机制（抖音特色，赢点常在这）

竞品常见打法是「产品话题 + 副话题」双挂：产品话题收品牌流量，副话题用猎奇/情绪词破圈。实证案例（2026-09-17 实抓）：#达霏欣防脱洗发水 累计 1,804,609 赞，而副话题 #把你头Peng了 单独承载 1,893,609 赞——副话题反超主话题。

给用户出抖音话题池时，主动配 1 个副话题候选：从产品最反直觉的点（成分/用法/效果争议）里造短句。

## 5. 泛词池与长尾

- 泛词必挂池：品类大词（#防脱洗发水 #洗发水 #防脱 这类），是流量入口。
- 长尾副标签补覆盖：场景词（#压力脱发）、人群词（#男生护发）、意图词（#防脱洗发水推荐）。

## 6. 前 3 秒钩子排序（实抓实证，2026-09-17）

抖音脚本开头句式按累计赞排序：反转/吐槽（实证累计约 181.8 万赞）> 权威定调（约 11.9 万）> 痛点直击+承诺（约 3.0 万）> 场景/价值观（约 1.7 万）。写口播脚本时开头 3 秒默认用顶层句式。

## 7. 接口故障纪律

- 同一接口连续 3 次失败（报错/空返回）即停手，写进交付的「数据缺口声明」。
- 不兜底硬爬、不换野路子、不编数。等接口恢复或换通道是唯一正确动作。
