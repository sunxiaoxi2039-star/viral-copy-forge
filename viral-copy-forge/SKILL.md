# viral-copy-forge · 爆款文案锻造流水线

给一个想投流的产品，跑完六段：

```
①输入与校准 → ②双平台采集 → ③竞品属性解剖 → ④标签火力实证 → ⑤组合生成 → ⑥质检与交付
```

产出一份「每句都能指回真实点赞证据」的爆款文案包。这套流程的逻辑很朴素：先看这个品类今天真的什么在火（拿点赞说话），再拆竞品爆款靠什么记忆点立足，最后把两者装进你的产品文案。流程里没有魔法，只有四件事：搬数据、提标签、拆竞品、重组生成。

## 四条总原则（六段都适用）

1. **先证据后结论**。每条「会火」的判断必须带赞数证据（哪条笔记/视频、多少赞、什么日期）。写「这个标签很有共鸣」但没有赞数，等于没写。
2. **只借机制，不抄原文**。竞品的句式、结构、钩子可以借，词汇必须换成用户产品的话。逐行改写竞品原文（洗稿）禁止：平台查重，也会烧掉账号信任。
3. **缺了就问，问不到就降级标注**。三件事缺一不开工：产品是什么、目标平台、投流目标。次要字段缺失用保守假设并标注。样本不足写「样本不足：仅验证 N/M 条」，数据没有写「无法验证」，不硬编。
4. **平台隔离**。小红书的赞只能证明小红书，抖音的赞只能证明抖音。跨平台证据可以互相启发句式，但不能互相冒充。

## 第①段 输入与校准

开工三问，缺任一先问用户，不得从语境推断：

1. 产品是什么、卖给谁——类目、价格带、核心卖点（≤3 个）。
2. 目标平台——小红书 / 抖音 / 双平台。
3. 投流目标——种草（涨心智）还是直转（要点击购买）。

再加一问：合规红线——有没有医疗、功效、认证类宣称？这类产品本段就按 references/compliance.md 的分品类矩阵升级，不等到⑥段。

竞品指认：让用户报 1-3 个对家。用户说不出，就按同品类、同价格带、同人群自拟候选并列出依据，请用户确认。竞品必须是能采到笔记的真品牌，禁止拿品类词当竞品名（「某防脱洗发水」不是竞品）。

产出：产品卡（套 templates/product-card.md）。闸门通过才进②段。用户催促也不跳过三问——问题问在开头，比返工便宜。

## 第②段 双平台采集

目标：拿到「标题 + 点赞 + 标签 + 日期」的原始行，小红书、抖音各一摞。

- 小红书：按 references/xhs.md。搜索词 = 品类词 / 竞品词 × 后缀词（教程/推荐/测评/合集…）。样本 30 条起步；必须带点赞；缺字段记 null，不当 0。
- 抖音：按 references/douyin.md。同品类词搜索；抖音火力看话题下视频的累计赞。接口连续 3 次失败就停手，把故障写进交付，不硬上不编数。
- 只有一个平台采得到：照常跑单平台，火力表标「单平台口径」，交付时说明另一平台的证据缺口。

## 第③段 竞品属性解剖

目标：把每条竞品爆款变成一行可组合的记录，并找到市场空位。

- 逐条拆爆款，用四列表：拆解项 | 证据（原文/赞数） | 分析结论 | 怎么复用（字段表见 references/formulas.md §1）。
- 竞品记忆点五问：产品形态 / 卖点昵称 / 使用仪式 / 信任装置 / 人群细分。
- 记忆点不可互换（防把竞品广告抄过来）：
  - 成分昵称：写下的昵称贴到用户产品上若仍像竞品广告 → 作废，下钻到体感/剂型/感官，直到贴上会别扭才算你的。
  - 使用仪式：禁止停在「打卡」二字——只抽出「打卡」= 弱仪式，不得作主结构；必须下钻到不可迁移的具体步骤。
  - 人群细分：禁止「宝妈/打工人」这类大词，必须用语料里的自我指认短语（如「发缝能塞进一根手指」）；抽不到就写「人群字段空」——空比假好。
- 空位识别：竞品都在做什么？没人做什么？没人做的那格，就是用户产品的差异化钩子候选。
- 三分法过滤：可迁移（钩子/结构/CTA/标签配法）直接拿走；需改造（语气/案例/受众）换皮后用；不可复制（名气/资源/人设经历）放弃，别假装能抄。

产出：竞品属性表 + 空位清单。

## 第④段 标签火力实证

目标：产出按累计点赞排序的火力表，让「什么标签会火」从感觉变成数据。算法（细节见 references/formulas.md §2）：

1. 汇总样本的中位赞；爆款线 = 3 × 中位赞（爆款是账号/品类的相对量，不是绝对赞数）。
2. 留下爆款线以上的笔记/视频，标签归一（同义标签并账）后聚合。
3. 每个标签记三件套：标签 / 火力证据（N 条爆款、累计赞、样本量、日期范围）/ 适用位置（标题钩子 or 正文结构 or 话题池）。
4. 入库门槛：出现在 ≥2 条爆款里的标签为「实证档」；只出现 1 条但赞数高的标「孤证档」，可参考不作强推荐。

火力闸门（规则级，防小样本失真与离群暴击）：

1. **平台样本闸门**：单平台有效样本 <20 条，火力表整表标「观察级」，禁止输出「实测最火」类表述；提示用户补 3-5 个竞品名扩样，用户拒绝则在交付物挂「样本不足」徽章。
1.1 **无日期降级**：同一平台超过 50% 的有效样本没有发布日期时，第 3 条时间衰减闸对该表失效，整表同样降为「观察级」——不知道哪年发的，就不能叫实测。
2. **标签最小样本闸**：主火力标签需小红书 ≥8 条含该标签笔记、抖音 ≥5 条视频；不够 → 只进「弱证据附录」，禁止当第⑤段主钩子，交付物标「样本不足，不宣称火力实证」。
3. **时间衰减**：火力计算默认只计近 90 天的互动；有按周粒度数据时改用按周指数衰减加权。老爆款不许躺功劳簿。
4. **离群封顶**：单条赞 > 同池中位数 10 倍，按 10×中位数计入累计；话题累计赞若单条贡献 >70%，不得标「品类主火力」，只能标「单条爆款句式，可借结构不可借权重」。
5. **最低门槛**：标签累计赞 < 类目 2 倍中位赞的，不进主推位，只进备选池。

指标纪律：只拿 likes 比 likes，views 与 likes 不混算；缺赞记 null 不当 0；每个标签带「最近实证日期」，超 90 天无新实证的标「过期待复验」，不删除（防误删周期性标签）。

产出：火力表（套 templates/fire-table.md）。

## 第⑤段 组合生成

目标：把「竞品属性 + 火标签 + 用户产品」装进文案公式，产出让陌生人愿意停下来的文案。

### 进⑤前的数据完整性检查（规则级，不是建议）

先校验双平台数据是否齐备。任一平台缺失：交付物显式标注「单平台证据」，且文案禁用一切跨平台措辞（「全网」「两个平台都火」「全平台验证」等）。没有抖音证据，就绝不说抖音的话——这句式上的越界比数据缺失更伤可信度。

### 主机制定结构（规则级：结构由胜出机制指定，禁止轮换公式）

- 先从火力表读出主机制，骨架跟着主机制走：主机制 = 专业背书 → 禁用 PAS 恐吓；主机制 = 反转钩子 → 第一分句必须是反转；主机制 = 成分昵称 → 禁再套「养发的尽头是 X」这类竞品已用过的骨架。
- 禁拼盘：主机制必须两平台同机制，或单平台过标签最小样本闸且另一平台无冲突机制。两平台机制冲突（一边医生背书、一边谐音反转）只准选一边做主；要打两个人群就出两条各打一边，禁止一条标题两边讨好。

选骨架（在主机制框定的范围内选）：
- AIDA（注意→兴趣→欲望→行动）：种草长文默认。
- PAS（痛点→放大→解决）：新品类教育、痛点尖锐的产品。
- FAB（特性→优势→利益）：卖点直给、直转场景。强转化文案批量时 ≤20%，用户明说投放模式才放开。

选切角：10 切角（痛点/反常识/误区/步骤/对比/故事/场景代入/清单/结果导向/强CTA）内部想满 10 个，只准交 3 条进交付，且 3 条首句句式不得同构（矩阵见 references/formulas.md §5）。批量多条时，条与条之间钩子、情境、说服顺序至少换一，只换词等于白写。

填充规则：竞品属性填数据位（数字/仪式/信任装置），火标签选钩子与话题池；每条文案后附证据行（这句用了哪个火标签、几条爆款多少赞背书）。

校准先行：先出 1 条样稿给用户过目，点头后再批量。批量配比 10:8:6:4:2（流量钩子:痛点种草:信任测评:产品需求:直接转化）。

### 出品四闸（规则级，每条产出必须过，不过就重写）

「稳但不出彩」是这类流水线最常见的失败方式：结构对、证据全，但读者划走。四道闸就是为锁死这个下限设的。

**闸〇 · 声明落地（Claim Ledger 前置到⑤，规则级，最先跑）**
产品卡或客户话术里任何被判「无证据／未核实／未备案／待补／驳回」的说法——成分浓度、资质编号、认证名、效果承诺、对比倍数——**一律不许进标题、正文、口播、标签、证据行**。
- 不许做刺点，不许加问号软化（「真的能 X 吗？」也算说了），不许写成「客服说」「听说」「据反馈」转述，不许作为换品名测试的排他属性。
- 它只能出现在两处：合规警示、数据缺口声明，并写明状态和补证办法。
- 想留住这个卖点：先要证据（报告编号、备案号、检测方），拿到才解锁；拿不到就换一个有证据的属性做刺点，宁可钩子弱一点。
- 自查一句：把标题和正文逐句问「这句的依据在产品卡哪一行？」答不出来的删。删到没有刺点，说明产品卡还没做完，回①补，不是在这里硬编。

**闸一 · 锚点与刺点**
- 锚点强制：每条标题至少含一个具体锚——数字 / 天数 / 价格 / 身份。禁止以形容词或抽象名词开头（「超好用」「宝藏好物」开头即废稿）。
- 刺点配额：每条标题必须含 1 个来自产品卡的不可公式化元件（规格/浓度等真数字、或物件/使用动作、或可指回语料的反转条件）。万能补丁黑名单：「有图有真相」「亲测有效」「闭眼入」「打工人必备」——命中即重写。
- 每批覆盖 ≥3 种情绪温度（冷静测评 / 紧迫感 / 冲突反问），同批不许切角同温——十条一个腔等于没写。

**闸二 · 换品名死亡测试**
把标题里的产品名替换成竞品名或任一虚构名：若句子仍通、卖点仍成立 → 判「品类通用句」，整条作废重写。过关标准：至少有一个属性是产品卡里竞品没有的。

**闸三 · 自评门**
每条成稿按四项 1-5 自评：钩子强度 / 证据密度 / 记忆点复刻度 / 换品名排他性。总分 <12 或任一单项 <3 → 重写，上限 3 轮；**交付评分最高版，不是第一版**。
打分锚点（防自评放水）：
- 钩子强度四问：数字具体吗？有反转或冲突吗？有人格声音吗（读者能说出谁在说话）？信息密度够吗（删句有损失）？
- 证据密度：几句指得回真实点赞数据或产品属性证据？
- 记忆点复刻度：竞品记忆点机制（昵称/仪式/信任装置/空位）是否被换皮复用到了你的文案里？
- 换品名排他性：品名换掉，句子是否就塌？

**闸四 · 洗稿判定**
借竞品句式只抽语法骨架，全部实体词（品类词/成分词/品牌词/场景词）强制替换成用户产品的。与竞品原文相似度 >0.6 判洗稿，重写。平台查重烧号，读者烧信任。

### 交付规则（规则级）

多条候选时，只交「换品名测试分最高、且刺点类型与其余不同」的那 1 条做主推，禁止交三条平均货；其余候选留档备查，用户点名要候选池才给。

产出：文案包（套 templates/copy-package.md），包内附自评分与闸门通过记录。

## 第⑥段 质检与交付

三道闸默认开：

1. **人味终检**：8 类 AI 腔反查（三段式套话/库存转场词/无出处权威/膨胀形容词/空洞对仗/通用开头结尾/列表腔/翻译腔），逐条改写。文案发给真人看，AI 腔既掉信任也不讨平台推荐算法喜欢。
   - 正文和口播是用户会**原样复制发出**的句子：一个括号批注都不许夹（「（A，痛点具象…）」「（说真话体）」这类），写法拆解和赞数全部挪进证据行。批注发出去就是「这号在套公式」的铁证。
   - 模板和参考册的示范句只教格式，不许照抄进交付物，哪怕只抄半句。背书同理：没有真实专家就用产品卡里可验的东西（配料表、工艺、实拍）去撑，不要每篇都请出同一个「朋友」。
2. **违禁词扫描**：极限词与绝对化用语、医疗功效越线、导流词（词表见 references/compliance.md）。
3. **效果闸（出厂三问，与 Claim Ledger 解绑，默认开）**：
   - 换品名测试⑥口径再跑一遍（独立复核⑤闸二）。
   - 来源可点：每个主标签必须指得回火力表带赞来源，指不回就删。
   - 证据行里的每个赞数必须是**本轮火力表**算出来的数字。模板页、参考册、别轮跑的示范数字（含 references 里的语料统计）一律不许当本产品的证据；确要引用通用语料，必须写成「通用语料，非本轮样本」并且不计入证据行。
   - 模板占位符（`〔…占位…〕`）和模板里的教学注解，一个字都不许出现在交付物里；出现即废稿重写，证据行宁可少一行，也不许留占位符冒充数据。
   - 平庸检测：命中万能补丁黑名单且无刺点 → 否决。
   - 一票否决回⑤；⑤重写两轮仍不过 → 回③补记忆点，不准靠润色蒙混。

Claim Ledger（证据台账）按品类分级（⑤闸〇已先拦一道，这里是复核）：医疗、功效、母婴、认证类强制开——每个卖点声明配证据位，无证据的声明直接删，不许软化成「可能」「据说」继续用；其余品类默认关，用户点名才开。

修复纪律：自动修复最多 3 轮，只改失败项，不整体重写——避免改着改着把事实改漂移。每轮改完必须重跑 `lint_package.py`，硬伤归零才算修完；脚本会给出硬伤所在行号，照着那一行改。闸〇命中（台账不认的说法还在文案里）时，整句换掉，标题的刺点也要换成台账认可的说法——只在闸门记录里写「已标待补、未使用」而文案原样不动，算作假。3 轮仍有硬伤，交付时把剩余硬伤原样列在交付包最前面，不许报「全部通过」。

交付规则：主推只交 1 条（见⑤交付规则）。交付必带五件：
- 文案本体（标题/正文/标签双池）
- 证据行（哪句用了哪个火标签，几条爆款多少赞）
- 合规警示（本品类的具体红线，不是「请注意合规」这种空话）
- 数据缺口声明（哪个平台没采到、哪个声明待补证据；「观察级」「样本不足」徽章挂这里）
- 丑话三句：标签只是把起跑线从 0 分提到 60 分；句式可借内容必须换皮；点赞不等于转化，钱的事在投放台测。

## 实战回写（贯穿）

用户发布后回填真实数据（曝光/点赞/转化），更新火力表对应标签的「最近实证日期」与表现记录；连续两次实战不行的标签降权出库。v1 靠人工回填，不做自动回流。

## v1 边界（明说不做）

1. 不代投流、不碰出价——点赞是「有人看」的代理指标，不是 CTR/CVR。
2. 不自动发布——生成完为止，发布动作留给用户。
3. 登录态采集是灰色通道——默认走公开数据口径；确需登录态时提示用户自己登录，尊重平台规则。
4. 没有投后数据闭环——回写靠人工，v1 不接投放台。

## 不该触发本 skill 的场景

- 用户只要润色/翻译已有文案，没有竞品与标签数据需求。
- 学术、法律、公文等严肃写作。
- 三问问不出产品信息，就没有原料——如实说明后收工。
